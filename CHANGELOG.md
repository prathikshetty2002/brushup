# Changelog

## 0.1.9

- **Pick a theme colour.** Under the Color field the Style tab shows a swatch for every colour the page's theme defines (`--color-*` custom properties on the root, which is what Tailwind 4's `@theme` produces). One click writes the theme's own class (`text-accent`) instead of a hex in brackets, replaces any colour class already on the element, and leaves the text size and weight alone. Projects with no `--color-*` variables simply show no swatches. The list is read from the page's own stylesheets, so nothing is guessed, and a token the page didn't list is never turned into a class.
- **Edit for one screen size.** In a Tailwind project the Style tab has a **Screen size** switch: *Every screen*, or *768px and wider* (named for how wide your window is, and written as the matching `md:` class). The second writes your change as `md:ml-4` instead of `ml-4`, replacing only the class that already has that same prefix, so other sizes keep their values. It works for every edit that writes a style: fields, nudging with the arrow keys, dragging and resizing. Checks fixes always apply to every size. Brushup refuses, with the reason, rather than write for every size when it can't write a class (a computed `className`, a plain HTML page, a project without Tailwind). A warning names a larger-size class that will still win. The switch is the first piece of responsive editing; it uses your window width, so resize it or use your browser's device mode to look at other sizes.
- **Edit for hover, focus and dark mode.** Under it a **When** switch offers *Always*, *On hover*, *On focus* or *Dark mode*. It writes `hover:bg-…`, `focus:…` or `dark:…`, and stacks with the screen size (`dark:md:hover:ml-4`). Only the class with the same prefix is replaced. The page can't show a hover or focus change until you hover or focus the element (and a dark change until dark mode is on), so Brushup skips its instant inline preview for these rather than show the change at the wrong time; the edit appears once your dev server reloads. A sentence under the switches says in plain words what the next edits apply to and how they are written.

## 0.1.8

- **Checked by hand, no code change needed:** Remix on Vite (`remix vite:dev` with the Brushup plugin) loads the canvas, and a nudge, a text edit and a delete each wrote to the route's JSX. On a plain HTML page in a real browser, delete, duplicate, reorder, wrap, alt text, the Decorative checkbox and an image upload through the file picker all wrote the right changes (an upload never overwrites an existing file: it saved `a-1.png` beside `a.png`).
- **Changes tab: one line of context** around each change instead of three, so a diff is short enough to show the edit without scrolling.
- **Layers: `index.tsx`, `page.tsx`, `layout.tsx` and similar are named by their folder** (`components/hero/index.tsx` is `‹Hero›`), and lower-case files get a name too (`ui/pricing-card.tsx` is `‹PricingCard›`). `app/page.tsx` itself stays unnamed.
- **Checks: a one-click fix for cut-off text.** Text that is clipped sideways gets "Show an ellipsis where it is cut" (`text-overflow: ellipsis; white-space: nowrap`), so it is visibly truncated. Other rules still have no fix button where the fix would need your words or a markup change.
- **Changes tab: long lines wrap, and the part that changed is marked.** A line of JSX with a long Tailwind class list used to run off the edge of the panel, so the edit itself was often out of sight. Lines now wrap with a hanging indent, a removed line and the added line that replaced it have the differing characters highlighted, and a file's diff opens scrolled to the first change instead of the top of its context.
- **Layers: components are named at their boundary, whether or not they forward props.** Before, `<FeatureCard>` only appeared when the component passed extra props through to its root element. Now an element written in a different file from its parent shows the component it belongs to, taken from the file name (`‹FeatureCard›`, `‹Hero›`), and the filter box finds it by that name. Lower-case files such as `page.tsx` or `index.tsx` are left unnamed, since they say nothing about the component.

## 0.1.7

- **Two new MCP tools, and a richer `brushup_inspect`: Claude can see the page without a screenshot.** `brushup_check` returns the Checks tab's findings as data: each problem, the element and where it is written, the standard or guideline behind it, and the style edit that fixes it. `brushup_console` returns the errors, warnings, uncaught exceptions and unhandled rejections the page has logged since the canvas loaded. `brushup_inspect` now also reports a stable handle (a short selector, and whether the element is mapped to source), its accessible name and role, its text contrast against the real background, what is on top of it at its centre, and which other elements overlap it. Seven tools in all. Checked end to end with a real MCP client against a running React Router app.
- **Delete and duplicate.** Select an element and press **Delete** to remove it from your source (its lines go with it, leaving no gap), or **Ctrl/Cmd+D** to write a copy right after it at the same indentation. Both are one undo step, in JSX and in static HTML, and work on several selected elements at once. They refuse, with the reason, rather than guess: an element drawn by `.map()` (one line makes many elements), one shown with `&&` or `?:`, one passed as a prop, the element a component returns, and `<html>`, `<head>` or `<body>`. An element *inside* a list item or conditional is ordinary markup and is fine (it edits the shared template; the status says how many elements share it). A copy that repeats an `id` warns.
- **A warning before Brushup mixes into your uncommitted work.** The first time it writes to a file that already differs from your last commit, the toast says so (`src/app/page.tsx already had uncommitted changes, so Brushup's edits are now mixed in with them in git. Commit first if you want them kept apart`), once per file per session. It stays quiet for files that match the last commit, files git doesn't track yet, and projects that aren't in git.
- **Swap an image and write its alt text.** Select an image and the Style tab shows an **Image** section: its source, a **Choose a file…** button, an alt text field and a **Decorative** checkbox, with a note when there is no alt text. Typing a new source or alt writes it to your JSX or HTML; choosing a file saves it into your project (`public/` for Next, Vite and React Router; beside the page for plain HTML, never over an existing file) and points the image at it, then puts the cursor in Alt text. Missing-alt issues in the Checks tab have a **Write alt text** button that jumps straight there. Safe by design: only an image's `src` and `alt` can be set, never `javascript:` or file addresses, and uploads are checked by their actual bytes (png, jpeg, gif, webp, avif; up to 2.5 MB; not SVG, which can carry scripts), named safely and kept inside the project. A `src` that comes from an import or variable (`src={logo}`) is refused with the reason. Quotes follow the element's own style.
- **Reorder and wrap.** Select an element and press **Alt+Up** or **Alt+Down** (or the Up and Down buttons in the Layers tab) to swap it with the element before or after it, or **Ctrl/Cmd+Alt+G** (Wrap in div) to put it inside a new `<div>`. Written to your JSX or HTML, one undo step each, in your formatting. A move keeps the element selected where it ended up. It refuses, with the reason, to move past an `{…}` expression or loose text (which could change what the page says), at either end of its parent, or for a list item. Wrap works anywhere an element can be written, including the element a component returns.
- **A Layers tab.** The page as a tree of its elements, with component usages shown by name (`<Button>`) and a hint (id, text or class) to tell siblings apart. Click a row to select it (Shift to add), fold branches, move with the arrow keys. Built for big pages: a filter box finds an element by tag, class, component name or text and shows each match in its place in the tree; the tree always starts folded, showing only the top level, so it never overwhelms; Expand and Collapse open or close every branch; selecting something on the page unfolds the tree down to it; and it lists up to 2,000 elements, saying how many it left out. It rebuilds after edits and leaves out the `<head>`.
- **React Router v7 (and Remix on Vite) now loads the canvas.** These frameworks render the page on the server, so the Vite plugin's usual place to add the overlay (`index.html`) never runs and no canvas appeared, even though elements were being tagged. The plugin now loads the overlay from the root route (`app/root.tsx`, or `src/root.tsx`) instead, once and in the browser only. Verified by hand in a real React Router 7 + Tailwind 4 app: the canvas appears, a text edit rewrote the JSX, and a nudge wrote `ml-2.5` onto the right element. Remix on Vite uses the same code path but hasn't been tried.

## 0.1.6

- **Ignore what doesn't fit, and the most serious comes first.** Each Checks card has an **Ignore** button, and a design kind has **Ignore all “Spacing” suggestions**, for deliberate choices. Dismissals are saved with the project in `.brushup/ignored-checks.json` (so they survive reloads, ports and browsers), listed under a collapsed **Ignored** section with **Restore**, and also left out of `brushup_check`, which reports how many it skipped. Accessibility kinds can be ignored one finding at a time but not wholesale. Groups are ordered by seriousness: accessibility standards first, then design guidelines, then conventions.
- **Nothing opens by itself.** Checks issues are grouped under a heading that names the kind of problem and counts it (a group of more than three starts folded), and each card is one line naming the element and what is off (`<h1> “Ship hhhh…”` over “Off the 4px grid: margin-top 23px”), so a run of the same problem doesn't read as repeats. A card opens to show the explanation, the fix buttons and the source only when you click it; a card stays as you left it when the page is checked again. The Layers tree always starts folded, and the Changes tab lists files closed.
- **A Checks tab: 15 accessibility checks and 11 design checks, with no AI and no tokens.** Filter by All, Accessibility or Design. Accessibility: text contrast, tap targets, small text, missing alt text, unnamed controls, vague links, skipped or empty headings, things that look clickable but a keyboard can't reach, a custom `tabindex`, autoplaying media, duplicate ids, and page basics (language, title, zoom, `<main>`, `h1`). Design: spacing off a 4px grid, over-long or tightly packed paragraphs, long centered text, headings that don't stand out, too many font sizes, cramped buttons (measured from the real gap, so fixed-height shadcn buttons aren't flagged), stretched images, clipped text, sideways scrolling, and text against the screen edge. Contrast, tap-size, small-text and most design problems have an Apply button that writes a normal, undoable style edit; the rest have Send to Claude, which pins a note.
- **Every check says where its number comes from.** Thresholds were checked against Figma's typography guide, Material Design, Apple's Human Interface Guidelines, WCAG 2.2 and Baymard's line-length research, and each issue shows the source with a link and whether it is a *standard*, a *guideline* or *common practice* (where no standard gives a number, it says so). Corrected along the way: lines flagged above 80 characters (WCAG 1.4.8), text under 11px (Apple's minimum), centered text from four lines. The tab says plainly that a clean result doesn't mean the page is accessible.
- **Fix: the canvas didn't see notes changed by an agent** when the project had no `.brushup` folder yet at start-up (a watch on a missing folder never fires). The folder is now created before watching.
- **A Changes tab.** Shows the git diff of your project against the last commit, file by file, with the files Brushup edited marked, a Copy diff button, and a refresh that happens by itself while the tab is open. Not in a git repo? It says so. The tour has a step for it.
- **The agent's reply is shown on each note** (“Claude: …”), under the note on the canvas.
- **An inbox for agents.** `brushup_get_notes` and `brushup_recent_edits` take `since` and return a `cursor`, so an agent only sees what is new. `brushup_update_note` takes a one-line `reply` (what was done), saved with the note. Manual edits are marked `locked`, with a rule saying not to revert them. The server now sends usage instructions to any agent that connects.
- **Fix:** reading notes no longer re-stamped every note's `updatedAt` with the current time.
- **`brushup init --agents`** sets up other agents too: the Brushup instructions go into `AGENTS.md` (beside anything already there), the MCP server into `.cursor/mcp.json`, and it prints the one command for Codex and the snippet for Gemini CLI. Idempotent, and off unless asked for.

## 0.1.5

- **The panel stays out of the way of what you select.** It re-checks after its fields have filled in, counts the element's handles and tag as part of the element, and when neither side of the page is clear (a full-width element) it shrinks into the free space above or below it, and when there's no room at all (a tall footer or section in a short window) it collapses to its header bar in the least-blocking corner. A chevron in the header collapses or expands it by hand.
- **Dark-mode contrast.** Text on the accent colour (Next, Save note, pins, the notes count) is dark in dark mode; white on the lighter vermilion was 3.1:1, now about 5.7:1.
- **Find-by-value leaves config alone.** `*.config.*` files and dotfiles are never searched or rewritten.
- **Message size cap.** The edit socket refuses messages over 4 MB.
- **The shared-rule switch says what it does.** Its hint reads “Off: only this element changes” / “On: every element this rule matches changes”, and a tooltip explains both.

## 0.1.4

- **A guided tour.** The `?` button in the panel walks through selecting, moving and resizing, the style fields, text editing, notes, undo and preview, highlighting each part as it goes. A dot on the button marks it until it has been opened once.
- **Panel polish.** The margin/padding widget has more room, selection handles draw behind the panel, and the shortcuts are an aligned list.

## 0.1.3

- **Text that comes from data can be edited.** Double-clicking `{f.body}` inside `items.map(...)` over a literal list in the same file now edits the string in that item of the list; `{"Save"}` and template-literal expressions are edited in place. Refusals say what the text comes from and why (a filter, a prop, state, a fetch).
- **Text is found by its value.** When the JSX doesn't hold the text (a prop, `useState("Save")`, a constant, a filtered list, a translation file like `messages/en.json`), Brushup searches the project for the one place that writes it and edits it there, with a warning that everything using that text changes too. If it's written in several places it refuses and lists them (`file:line`); tests, stories and `node_modules` are ignored; text under 3 characters isn't searched.
- **A note is pinned when the source can't hold the text.** For text from a database, an API or a CMS, the canvas restores the text and pins a note on the element (“Change this text to X (it says Y)”) so Claude can make the change with full context. Repeating the same edit doesn't pin a second note.

## 0.1.2

Windows fixes, found by driving real Vite and Next.js apps in a browser on Windows CI.

- **Elements are tagged when the project folder has two spellings.** On Windows the same folder can be `C:\Users\RUNNER~1\...` (an 8.3 short name) for the root and `C:\Users\runneradmin\...` for a file; Brushup called every file "outside the project" and tagged nothing. Drive-letter case, symlinks and junctions hit the same check. Real paths are now compared when the plain comparison says "outside".
- **Edits are accepted on Windows with Vite.** Vite gives the plugin its root as `C:/proj` while every path built from it uses backslashes, so every edit was refused with "Bad element reference". The root is now normalised once.
- Tests build their file paths for the current OS; the smoke test tolerates Windows holding its temp folder.
- CI now drives the canvas in Chromium, Firefox and WebKit on Linux, macOS and Windows, and builds real Vite and Next.js apps on all three.

## 0.1.1

- **Elements are found by what they say in the source, not where they were.** Each dev-mode tag carries a version token (a hash of the file and a fingerprint of the element). If the agent edits the file under the page, the element is found again by its fingerprint; if that is ambiguous the edit is refused instead of landing on a look-alike. `strict: false` restores the old behaviour.
- **Types for `require()` users:** `.d.cts` files for `brushup/next` and `brushup/vite`, plus the `strict` option in the types. 0.1.0 made TypeScript report these as ES-module-only under node16 resolution.
- **Setup:** `brushup init` handles the Next.js Pages Router (wires or creates `_document`) and a Vite config with no `plugins`, and follows a file's import style.
- **Canvas:** rubber-band selection, snapping guides while dragging (Ctrl/Cmd moves freely), resize from every edge and corner, `flex-basis` for flex items, and an explanation when the page refuses a size (`max-width`, `flex-grow`, grid track, …).
- **CSS Modules:** the shared-rule option edits the module's own rule for `styles.card`-style classes.
- **MCP:** `brushup_inspect` accepts `note_ids` to inspect several notes' elements in one call; the server reports the real package version; `brushup --version`.
- **Verified in CI:** Windows, macOS, Node 20.9, 22 and 24, and the canvas driven in Chromium, Firefox and WebKit. Also tested by hand on Next 15.5 (webpack and Turbopack) with Tailwind 3.
- Fixed a Windows-only test path bug and a `magic-string` ESM-only dependency that broke `require('brushup/next')` on older Node (in 0.1.0 already patched before release).
